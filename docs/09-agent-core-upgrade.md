# NEXIOM 0.3 Agent 核心升级

更新日期：2026-09-18。

## 实际基座

当前直接运行官方 Codex 0.154.0 原生 `app-server`，使用标准输入输出上的 JSON-RPC 协议。推理循环、工具选择、项目指令加载、沙箱、原生会话历史和自动上下文压缩均由 Codex 完成。NEXIOM 负责桌面交互、项目级执行确认、任务记录、协议适配和项目记忆管理。

相比 0.2 的 SDK `exec --json`，app-server 提供真正的消息增量、命令输出增量和上下文统计。因此这次切换协议入口，没有另写推理循环，也没有在前端拆分完整答案来伪造打字过程。

协议依据为已固定的公开源码：

- 仓库：<https://github.com/openai/codex>
- 标签：`rust-v0.154.0`
- 提交：`6b9826e3aa83b1a5947db50f4332cb9c65f1b340`
- 类型定义：`codex-rs/app-server-protocol/schema/typescript/`
- 协议适配实现：`packages/runtime/app-server.ts`
- 既有 SDK 源码、许可证及来源记录仍位于 `vendor/codex-sdk/`，继续作为共用事件类型的来源。

当前没有运行 Claude Code 内核，也不宣称可以复制未公开、未获许可的 Claude Code 实现。产品可以借鉴公开交互，运行时身份和能力必须如实呈现。

## 数据与模块边界

| 模块                             | 职责                                                                   |
| -------------------------------- | ---------------------------------------------------------------------- |
| `packages/runtime/app-server.ts` | 管理一个任务独占的原生进程、JSON-RPC、事件转换和进程树结束             |
| `packages/runtime/codex.ts`      | 解析官方内核位置、原有登录配置、自定义模型连接、项目级指令和沙箱参数   |
| `packages/core/agent.ts`         | 执行确认、幂等任务、原生线程绑定、真实流式消息持久化、上下文记录和取消 |
| `packages/core/memory.ts`        | 项目记忆文件的读取、版本检查和原子保存                                 |
| `packages/core/service.ts`       | 工作区迁移、受验证的命令接口、项目/会话数据                            |
| Renderer                         | 展示真实消息状态、工具记录和可编辑记忆，不负责模型推理                 |

SQLite 从版本 2 增量迁移到版本 3，新增 `agent_contexts`，保留原有项目、消息、任务、SDK 线程绑定和事件。高版本工作区会被旧应用拒绝打开，避免降级写坏数据。

## 原生事件

- `item/agentMessage/delta`：累计到同一 `AgentItem.item.text`，状态为 `running`。
- `item/completed`：采用引擎返回的权威完整内容，状态变为 `completed`。
- `item/reasoning/summaryTextDelta`：仅接收公开分析摘要。原始内部推理 `item/reasoning/textDelta` 不进入 UI 或 SQLite。
- `item/commandExecution/outputDelta`：保留真实命令输出；完成时记录退出码。
- `turn/plan/updated`：展示原生计划进度，步骤完成状态由引擎决定。
- `thread/tokenUsage/updated`：保存引擎实际给出的上下文窗口、累计 token 和最近一次模型调用用量。
- `contextCompaction` 完成事件：记录由原生内核完成的压缩次数。

未知上下文窗口为 `null`。累计 token 是整条会话的消耗，不能除以上下文窗口来显示占用率。最近输入 token 是上次请求的历史观测值，也不应被描述成精确实时占用。

任务用量使用本轮结束累计值减去本轮开始基线，包含一次任务中所有模型调用。恢复线程时使用固定 0.154.0 内核的 `initialTurnsPage` 分页恢复协议，仅获取一条历史摘要并接收原生历史 token 重放，避免加载整条长历史。此字段属于实验协议，因此受固定内核版本约束；未获得可靠基线时任务用量为 `null`。按 `turn/start` 返回的任务标识排除历史通知，原生最近单次用量继续独立保存到上下文状态。

## 项目记忆

记忆是项目内的 `.nexiom/MEMORY.md`，内容由用户审核和保存，适合记录已确认的假设、数据口径、团队约定、模型选择和待验证结论。它不保存隐藏思维链，也不自动把临时推测提升为长期事实。

- `memory.read { projectId }` 返回 `ProjectMemory`：文件路径、内容、SHA-256 版本和更新时间。
- `memory.write { projectId, text, expectedRevision }` 使用版本检查，外部编辑产生冲突时拒绝覆盖。
- 正在执行任务的项目不能修改记忆，防止本轮上下文中途变化。
- 记忆目录和文件拒绝符号链接；保存使用同目录临时文件和原子替换。
- 每次提交任务都重新读取项目记忆，并传给原生线程指令；事件记录所使用的版本摘要。
- 新会话可以读取同一项目记忆；旧会话恢复仍使用 Codex 原生历史。

## 权限与退出

规划模式为原生 `read-only`。执行模式必须经过本次任务确认，使用 `workspace-write`；子命令网络访问由已有设置决定。协议层不会默许额外权限升级。

取消任务会结束本轮独占的 app-server 进程树，包括其正在运行的程序，保留已发生的文件修改和已经收到的输出。下次启动不会自动重放中断任务。设置中的自定义 API Key 仅通过宿主进程内存传入环境，不写入项目记忆、上下文记录或 SQLite 设置。

## 已完成验证

运行 `npm test` 的 22 项自动测试通过，覆盖原有工作区行为、执行确认、幂等任务、线程恢复、流式事件、公开摘要过滤、上下文指标、压缩事件、记忆冲突与取消，以及多调用用量累计、恢复基线和 JSON 工具输出脱敏。

另使用实际登录模型执行 `node tests/live-agent-smoke.mjs`：

1. 创建并实际运行 Python 最小二乘脚本，验证 `slope=2`、`intercept=1`、`rmse=0`。
2. 观测到 126 次非空的原生实时文本更新。
3. 完全关闭并重开 Core，再次提交任务，恢复同一原生线程。
4. 模型正确回答上一轮数值，以及用户保存的项目记忆核验口令。
5. 收到真实上下文窗口和 token 统计。

`node tests/live-agent-cancel.mjs` 另启动了真实 Python 等待进程，点击对应取消接口后确认任务为 `cancelled`，Python 子进程已经退出。

`node tests/live-sdk-migration.mjs` 另外通过旧 SDK `exec` 创建原生会话，再经 app-server 恢复同一会话，准确复述 SDK 轮次中的口令。实测恢复轮次用量为输入 16585、输出 11，正确排除历史累计用量。

这三个 `live-*` 脚本需要已配置模型且会消耗实际模型调用，因此不纳入默认 `npm test`。自动压缩事件有协议测试，但本次短任务没有触发实际长上下文压缩；自定义 API 供应商的网络连接也未在本轮逐一实测。

## 后续边界

尚未提供手动压缩、历史分叉、工具权限逐项审批、跨项目向量检索、自动事实记忆提取、实验版本数据库或论文导出。MCP 的原生调用事件能够展示，但专门的 MCP 配置和交互授权界面仍待开发。当前源码没有声称这些功能已经完成。
