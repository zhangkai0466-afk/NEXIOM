# 逐附件分析工作台

导入后由 Core 按清单顺序启动独立附件任务。每份文件使用独立模型上下文，只读取当前附件；同一外层运行负责取消及整体状态，前一份报告保存并结束输出阶段后才启动下一份。任务调度不依赖工作台是否打开。

每份附件只显示阅读、分析、思考、输出四个阶段。`nexiom_attachments.set_attachment_stage` 记录真实工作目标的开始、完成和失败，内部命令和反复核查不添加节点。阶段无固定时长；`publish_attachment_report` 在输出阶段保存以附件 ID 关联的报告，保存前不能结束输出阶段。

单份报告和阶段事件随现有 Agent 记录持久化。中断保留已收到的内容，工作台支持单份重试和继续未完成附件；重启不自动重新运行。人工纠偏仍单独处理目标文件，并带入这份文件已有报告，保留此前有依据的修正。

旧报告兼容 `## [A01] 文件名` 和 `## A01 文件名`，不把全局结论并入最后一份附件。未识别报告、任务失败或停止均留在工作台，显示原因与已收到的输出。只有用户主动导入新附件才返回导入页。

附件列表和纠偏栏都支持拖动分隔线、方向键调宽并记住宽度；窄窗口保留横向滚动。执行记录默认折叠，不混入四阶段主进度。

验证包含阶段顺序、跨附件拒绝、逐文件独立上下文、保存后继续、取消、输出失败、局部重试、纠偏、重启恢复、旧标题兼容和真实原生引擎接收阶段/报告工具调用。本地模拟供应商验证不消耗真实模型额度；页面验收材料位于 `output/playwright/attachment-workspace-*`。
