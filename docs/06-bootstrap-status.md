# 0.1.0 基础版范围

本轮依据用户提出的初步搭建意向，实现可运行的本地工作区。它验证桌面、独立核心、持久化和真实只读工具链，尚未完成路线中的 P0/P1 全部验收。

## 已落地

- Electron + React + TypeScript，使用已有 NEXIOM 品牌图片。
- 桌面 Main/Preload/Renderer 分离；Renderer 不具备 Node 和任意文件访问权限。
- Core 在 Electron utility process 或开发环境 Node 子进程内运行。
- 项目、会话、笔记、运行与事件保存在 SQLite；状态改变后通知界面刷新。
- 真实文件导入、受项目范围限制的读取和只读检查；同名文件拒绝覆盖。
- 工具记录可展开；普通笔记和核心反馈分开显示；未连接模型时不模拟分析。

## 当前暂定实现与设计差异

| 项目 | 当前基础版 | 后续边界 |
| --- | --- | --- |
| 持久化布局 | 一个本地工作空间数据库存全部项目元数据，项目文件独立目录 | 项目导出及迁移前实现设计中的每项目数据库；当前不能仅复制项目文件夹恢复会话 |
| 核心通信 | 类型化本地 IPC 请求/响应；开发预览经 localhost HTTP/SSE 转发 | 沿用命令/事件边界；暂不实现完整 JSON-RPC stdio 协议 |
| 历史投影 | 读取完整会话快照，事件页仅最近 500 条；工具状态持久化 | 大规模项目需分页与事件游标；不声称无限历史事件回放 |
| 执行能力 | 手动触发内置只读检查，导入用户明确选定的附件 | 不包含模型循环、任意 shell、生成代码执行或审批状态机 |
| 运行恢复 | 核心重启将未终结检查标为 interrupted，不自动重放 | 后续增加外部工具未知结果对账及工作进程取消 |
| 并发 | 一个工作空间只允许一个 Core；同项目同一时刻一个检查 | 不支持两个独立工作空间对同一外部目录的协同写入 |

这些选择用于尽早验证产品操作，不替代原架构目标。Core 的文件范围检查不等于 OS 沙箱；当前没有对用户程序作隔离承诺。
