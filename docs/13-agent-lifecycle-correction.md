# 0.3.2 任务生命周期修正

日期：2026-09-18。

## 问题与责任边界

0.3.1 的 `timeoutMinutes` 默认 15 分钟、最多 60 分钟。它由 NEXIOM 的 `AgentCoordinator.perform` 用定时器触发 AbortController，强制停止整个 Agent turn，正常的编程和数值实验也会被截断。这是 NEXIOM 在封装层额外加的限制，不是 Codex app-server 的要求，不适合作为持续自主工作的默认行为。

0.3.2 删除设置字段、设置页面输入、执行确认里的时间文案，以及实际触发取消的定时器。旧 settings 仍可读取，Zod 会忽略已移除的 `timeoutMinutes`；其他字段、项目、历史及凭证不需要清除。没有通过改为更大的默认值来保留同样的问题。

## 生命周期

启动 turn 后持续读取原生事件，由引擎完成/失败、用户停止、应用关闭或实际进程/连接故障决定本轮结束。不会因为经过固定分钟数而中断整轮工作。当前用户停止和退出仍会终止该运行拥有的进程树；后台服务、关闭窗口后继续任务及原生 interrupt 的优雅退出升级是另行设计的能力。

保留的超时有明确范围：

| 范围 | 当前实现 | 含义 |
| --- | --- | --- |
| 桌面界面挂载 | 15 秒 | 未显示 UI 时提供启动恢复提示，与 Agent 任务无关 |
| 本地 Core 命令回应 | 30 秒 | `agent.submit` 立即返回 runId，不等待 Agent 执行完成；该回应超时不会主动取消任务 |
| app-server RPC 确认 | 30 秒 | 当前用于初始化、线程开始/恢复、turn 启动等短确认；`turn/start` 返回 inProgress 与 turnId 后，后续通知流没有整轮定时器 |
| 引擎就绪探测 | 10 秒 | 引擎版本/认证检测进程的等待范围 |
| 进程退出清理 | 3 秒后补充终止 | 发生关闭后确保拥有的进程退出，与正常运行时间无关 |
| 原生命令工具 | 由 Codex 工具实现控制 | 单个命令的执行/等待时间不会被当作 NEXIOM 整轮任务预算 |

未来如果用同一 RPC 客户端新增等待命令完整退出的 `command/exec`，必须重新选择该请求的超时策略，不能机械套用 30 秒。

## 对官方行为的核查

- 已读取 [OpenAI 官方 App Server 文档](https://developers.openai.com/codex/app-server)：`turn/start` 开始一轮并持续接收通知；`turn/completed` 表示完成状态，`turn/interrupt` 请求取消。此生命周期不需要客户端另加 15 分钟总时限。
- 已读取 [Claude Code 官方环境变量文档](https://code.claude.com/docs/en/env-vars)：存在 API 请求超时和 Bash 命令超时。因此“界面没有整轮任务时限”不等于“底层不存在任何超时”；需要按作用范围区分。

本次修正的是 NEXIOM 任务编排层与所选 Agent 交互的偏差。Codex 原生工具循环、会话恢复和压缩仍在使用；这不表示桌面已经完整映射原生的所有审批、中途输入和后台任务能力。

## 验证

23 项核心测试全部通过。新增回归用旧 SQLite 设置重开，确认其他字段保留且 `timeoutMinutes` 不生效；用虚拟时钟推进 16 分钟后继续至两小时，任务仍运行且随后正常完成。原有手动取消测试继续通过。这是可重复的时钟模拟，不声称实际消耗模型运行了两小时。

0.3.2 打包 EXE 验证通过：设置页面和执行确认均无整轮时限，主题、配置/记忆保存、草稿保留、密钥重启恢复及渲染进程恢复正常。桌面快捷方式已更新至 `release/NEXIOM-0.3.2-win-x64/NEXIOM.exe` 并完成普通启动。

仍保留输出大小与事件积压保护；移除时间上限不表示任务在连接故障、资源不足或用户退出时也能无限运行。
