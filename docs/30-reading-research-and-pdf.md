# 研读阶段、文献核验与 PDF 阅读

## 展示时机

输入赛题并开始研读后，工作区只展示阶段动画链及停止按钮。材料清单、过程文字、工具命令与流式报告均不在运行中显示。即使已经收到完整报告标题或某个 `agent_message` 已完成，只要整轮 `Run` 仍在运行，不能进入报告工作台。

阶段由 `nexiom_reading.set_reading_stage` 报告实际开始/完成，不按时间自动推进。基本顺序是：思考（可选）→阅读→分析→思考复核→按需检索→思考核验→编写。起始思考仅用于实际发生的任务理解、确认文件或选择读取方式，首个实质性研读工作必须完整阅读原题；可以直接从阅读开始。没有关键歧义时省略检索及其后专门的核验；未允许联网时不能开始检索，也不能补出未发生的阶段。检索后必须先思考核验，再编写。

工具只接受阶段标识和状态，不采集内部推理。主链按工作目标汇总为 4～7 个节点：可选起始思考、阅读、分析、思考复核、可选检索及其后思考核验、编写；运行中只展示实际已发生的部分。阶段内分批读文件、逐页检查、逐问分析、多次搜索、多来源阅读、局部回看以及短暂思考不增加节点。多轮查证汇总在同一组检索/核验节点内。内部记录不删除，底层仍允许真实重读、再次分析、思考、检索回访及失败重试，不拒绝第 8 条及之后的真实阶段事件；由前端汇总到有限主链，不截断工作。只有实际工作目标切换到已结束阶段时才上报回访，使用新 `stepId`；不是每次重读都必须新建阶段。真实重读仍经过阅读→分析→思考，检索回访后仍须思考核验，不能任意跳步。

显示严格依据已确认的阶段事件；未确认当前阶段完成时，不显示后续阶段，即使部分到达的快照里后续已经完成，也不得据此把前一步补成成功。同一时刻最多一个运行节点。取消、失败和未结束的步骤不得标绿勾；失败与真实重试依据实际事件显示。所有思考节点统一显示“思考中”或相应结束状态，黄色只对应真实思考，不再使用“准备中”或“研读中”作为黄色兜底。等待第一条阶段事件及旧会话缺少阶段记录时仅显示中性的运行提示，不据此推断模型在思考，也不生成主阶段或完成节点。

读取前收到真实的原生思考活动时可以立即展示起始思考；有明确完成记录才保留为完成节点，正式阶段开始不能替缺失记录补成功。读取失败后的思考归入读取恢复，不倒插为起始思考。回访节点显示本轮实际动作，重复检索使上轮核验暂时变为灰色“待思考”，直到新的核验事件到达；重试结果更新同一工作节点，完整失败记录仍保留在后台。整轮停止、失败或中断均显示独立的终止提示，即便此前所有已记录阶段都完成。最终成功标记复用编写节点，不额外添加第八个节点。

阶段完成以工作结果为准，不以调用返回或节点数量为准：

- 阅读：覆盖可读取的题干、各小问、公式、图表和附录，保留原文位置，并明确缺页、解析失败及未读全之处。
- 分析：全部小问的目标、输入输出、约束、单位、时间范围和交付要求形成完整结构，区分题面事实、上下文解释与尚未说明的事项。
- 思考复核：关键解释、信息边界和跨问关系有题面依据，可以整理报告，或已经确定具体查证疑点及其影响范围；不能联网的疑点明确列为待核对。
- 检索：围绕具体疑点取得并阅读能够取得的必要依据，或明确记录来源不可得、证据不足及其限制；搜索返回并不代表完成。
- 思考核验：将查证结果放回全题复核，疑点得到解释，或明确来源冲突、证据限制、影响范围和待人工决定项。
- 编写：报告完整、与依据一致、关键判断可追溯、未解决事项已列明，文稿检查与修正完成。

上述边界不限制阶段内部的工作量。不能为保持短链提前结束研读，也不能把推测或未解决争议写成已确认事实。

相邻阶段上报之间保留已有节点，不显示“等待下一阶段”，也不把上报间隔单独做成一个环节；下一条真实阶段事件到达后直接接入原链。计时和停止按钮持续可用，已确认的完成事实不因衔接需要而改回进行中。

整个短链在正文可用区域水平、垂直居中，阶段增加时使用位置过渡平滑调整整体位置，不缩放字形。汇总后的节点超出可用高度时才产生内部滚动；计时与停止按钮置于独立底栏，不覆盖节点。连接线生长、节点渐入和完成态淡变相互衔接；快速到达的节点短暂错峰，额外等待最多 220ms。需要滚动时使用保留速度的连续跟随，窗口改变尺寸时跟随当前工作；手动查看其他节点后停止自动跟随，可点击“回到当前阶段”恢复。完成后可通过“研读过程”回看按相同规则汇总的阶段链，不重新展开成工具或回访流水。

成功终止时短暂显示最终完成态，再展示报告。减少动态效果或历史报告直接进入报告，不补演动画。失败轮中的未完成报告不作为最终报告发布。

动作链底部显示本轮“已用时”，按任务开始时间每秒更新，阶段切换和重新进入页面不归零；完成、停止、失败或中断后依据保存的结束时间显示固定“总耗时”，历史回看仍保留。时钟单独渲染，不触发动作链重绘。超过一小时显示时分秒；缺少可靠结束时间的旧记录显示 `--:--`，不继续累计。

## 研读与人类协作

`packages/contracts/reading-workflow.ts` 统一定义研读规则和报告结构，运行时注入阶段规则，初始研读及纠偏请求复用报告结构。核心要求如下：

- 术语分为影响解题的关键口径、背景知识和尚无法判断。关键口径说明会改变哪一问的公式、约束、目标或结论；背景知识不进行无目的文献堆积。
- 对关键歧义真实检索国家/行业标准和主流同行评议文献，核对版本、有效性、适用边界、公式与原文位置，记录 DOI/URL。摘要、二手转述、不可取得的全文必须标明证据限制。
- 将题面定义、外部定义和工作假设分开；冲突并列比较，给出推荐、理由及待人工决定项，不擅自替人选择。
- 检查决策时点可用信息、未来真实值、全样本预处理、训练/验证/测试隔离及事后完美信息解。零购电等极端结果是需要核验的信号，不预断正确或错误。
- 对后问逐项核对“继承、修改、不适用、待核实”，不按问题先后顺序自动继承前问策略和信息条件。
- 研读阶段称人工纠偏，允许多轮反馈并核查连带影响。建模阶段称想法分享、共同讨论，不将所有建议自动解释为错误修正。
- 严禁输出可行路线、建模建议、模型/算法推荐、求解步骤或方法排名；术语推荐仅限有据的题意解释，不能延伸成建模方案。重新生成旧报告时也要求移除这些内容。
- 长篇解释、文献论证、歧义和理由直接用正文；表格只用于必要、短小的横向比较，通常不超过四列。已有报告中的长篇宽表在阅读界面转换为标题和带标签段落，保留链接、公式和单元格内容，不改动存储原文；简表继续保留。

这是一套行为要求和工具支持，不能保证模型识别所有陷阱。用户的充放电效率、紧急购电与跨问继承例子只转化为通用检查方法，不被硬编码成任何赛题事实。

输入赛题界面只提供导入、文件清单和开始研读，不提供 PDF 预览。研读完成后，从报告目录的原题文件进入 PDF 阅读。

人工纠偏栏展开、收起都有过渡。拖动正文右侧分界线可以实时调整宽度，通常为 280–560px，并根据正文剩余空间限制上限；向右拖至 160px 时自动收起，重新打开恢复收起前宽度，未提交草稿保留。键盘左右键调整，Home 收起，End 调至可用最大宽度。减少动态效果设置会关闭过渡。

## 联网与隔离

研读阶段在 NEXIOM“允许程序联网”启用时提供原生 `web_search=live`，规划模式仍不授予文件写入或程序网络访问。其他阶段不因这次修改自动增加网页检索权限。联网关闭时要求报告待核验来源及原因，不得绕过设置或声称已经检索。

供应商需要支持原生网页检索；不支持、失败或证据不可得时明确报告限制。会话指纹包含研读能力版本和联网设置，避免旧线程丢失工具声明；不加载个人 Codex 配置和技能。

## PDF 阅读

复用 PDF.js 官方 Viewer、FindController、LinkService 和批注能力，支持：连续分页、页码跳转、缩略图与文档书签、选择文字、跨页搜索与大小写匹配、自动/适宽/适页/倍率缩放、旋转、全屏、高亮/手绘批注、下载含批注副本。工具栏按目录与批注、页码与缩放、搜索与下载分组，PDF 直接占满正文阅读区域。中文 CMap 与标准字体随应用打包，不依赖外部字体请求。

Ctrl+鼠标滚轮以指针位置为基准连续缩放文档，限制在 10%–1000%，不改变应用缩放；普通滚轮仍用于滚动。PDF.js 样式通过 `@scope (.nexiom-pdf)` 隔离，不允许影响应用侧栏等同名类。

批注属于 PDF 阅读副本，下载后保存在用户选择的位置，不自动覆盖原赛题，也不自动变成 Agent 人工纠偏。需要影响研读结论的修改仍在人工纠偏区提交。

这是基于 PDF.js 的常用阅读功能，不声称复制 Edge 全部能力。按需求移除打印，不提供朗读、翻译或 Acrobat 编辑入口，也未提供 OCR、签名和云同步。扫描版 PDF 无原始文字层时不能凭空搜索或选中文字。

本轮通过隔离样例验证阶段回访、提前报告隐藏、成功切报告、失败/停止及人工纠偏再次进入动画；原生引擎对接本地模拟供应商验证实际阶段工具回调与联网开关。未调用收费模型，未声称对用户举例的赛题或真实文献进行过实证核验。

本次细化在 Edge 验证 Ctrl+滚轮、普通滚动、目录、缩略图、搜索、跳页、全屏、高亮和批注下载，以及纠偏栏的快速开关、拖动、自动收起、键盘操作和减少动态效果。检查 1360×900 桌面窗口、1920×1080 全屏及应用规定的 760px 最小桌面宽度，没有进行手机适配检查。长表转正文后的公式、链接正常，主界面侧栏未被 PDF 样式影响。未发现受测区域的工具栏越界、正文重叠或未捕获页面异常；损坏 PDF 能显示错误状态。生产安装包未在本轮自动替换。
