# NEXIOM 0.3.1：全页设置与普通启动修复

日期：2026-09-18。

## 本版行为

设置改为独立全页：窗口顶栏、左侧返回应用/搜索/分类，右侧居中分组内容。常规、外观、模型连接、项目记忆和关于均对应真实能力。会话组件在设置打开时隐藏保留，返回时恢复输入草稿、阅读位置和焦点；配置草稿在切换分类时保留，离开时支持保存或放弃；记忆另有保存与版本冲突检查。

主题继续支持暗色、浅色、跟随系统，与 Windows 标题栏同步。新增加载页面、React 错误边界和本地启动日志；存储被限制时外观偏好使用本次会话内存，不阻止界面启动。

## 普通启动问题的复现证据

旧 0.3.0 使用 `show:false`，仅在 Chromium `ready-to-show` 事件到达时显示窗口。真实用户目录下的普通快捷方式启动出现进程存活但窗口隐藏；通过 Win32 枚举能找到不可见的 NEXIOM 窗口，强制显示后只有背景色。带调试端口启动则可以成功，不可用其结果代替普通启动验收。

随后给桌面宿主添加日志，用不带调试端口的启动记录到 `dom-ready` 和 `did-finish-load`，但没有 `ready-to-show`。本版窗口直接显示，并单独确认 React 已挂载，不再把唯一显示入口依赖在首次绘制事件上。第二实例打开也会显式显示并聚焦已有窗口。

这是已复现并修复的启动缺陷；目前没有证据将其归因于某块显卡、ToDesk 驱动或 Thinking Orbs，因此没有默认关闭硬件加速。未删除用户缓存、项目、会话数据库或凭证。

## 故障恢复和日志

- 主框架每次加载都启动 15 秒挂载监控，包括恢复按钮触发的重新载入。
- 加载失败、preload 初始化失败、渲染进程退出或窗口无响应时提供原生恢复提示。
- React 渲染错误显示可操作的恢复页；资源加载前的 HTML 自身包含启动提示和重新载入链接。
- 日志默认在 `%APPDATA%\NEXIOM\logs\startup.log`，记录应用版本、生命周期、加载/挂载、进程退出等元数据。超过 1 MB 时轮换；不记录任务正文、密钥或命令内容。
- 修复内嵌字体被 CSP 拒绝的问题，允许本地和 data 字体来源，其他远程脚本限制保持有效。

## 发行与验收

新版位于 `release/NEXIOM-0.3.1-win-x64/NEXIOM.exe`。这是 Windows 便携发行目录，应保留 EXE 旁边的资源与原生引擎文件；不是单文件安装器。桌面快捷方式指向新版本，脚本从 package.json 读取目标版本，旧发行目录保留。

实际验收结果：

- TypeScript 检查和生产构建通过；22 项核心测试全部通过。
- 浏览器设置流程 14 项断言通过：全页布局、分类/搜索、草稿保留、配置保存/放弃/校验、主题/字号/减少动画、记忆草稿及保存；1440×960 和 540×860 无水平溢出。
- 打包后的 EXE 在隔离目录验证全页设置、暗浅主题、会话输入 DOM 保留、配置与记忆未保存保护、系统加密密钥保存/重启恢复；未启动模型任务。
- 故障注入：让 localStorage 读写抛出异常，界面仍成功加载；强制崩溃 Renderer 后，宿主提供恢复提示并成功载入新的界面，Core 保持可用。恢复提示在自动化中自动选择重新载入。
- 真实用户目录中，用更新后的桌面 `.lnk` 完成两次不带任何调试参数的冷启动；Win32 原生窗口截图显示完整界面，日志确认 `renderer-ready`。最小化后再次打开快捷方式，原有窗口恢复且未创建第二个核心。
- 普通冷启动主进程 PID 96700、重开 PID 15484；启动日志仅用于本次证据定位，不应当作为稳定进程标识。

可复验脚本：`output/playwright/desktop-v031-check.cjs`、`settings-smoke.js`、`capture-native-window.ps1`。截图位于 `output/playwright/v031-settings-{dark,light}.png`、`v031-shortcut-cold-start.png` 和 `v031-shortcut-reopened.png`。测试项目位于 `.local/desktop-v031-check-*`，没有创建到实际用户项目列表中。

原生远程 Agent 执行继续使用 0.3 已实测的 Codex app-server。本轮没有重新消耗模型请求，也没有验证所有 GPU/驱动组合；上述结论覆盖本机实际快捷方式和自动化故障恢复。
