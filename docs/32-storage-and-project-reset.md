# 存储清理与项目重置

设置 → 应用 → **存储与清理**提供缓存占用、重新计算和清理按钮。清理完成后报告实际释放空间；正在使用、无法访问或发生变化的文件会保留并提示。

缓存范围为 NEXIOM 私有运行环境的 `runtime/home/.cache`、绘图字体缓存 `runtime/visual-design/matplotlib`；桌面版额外通过 Electron Session API 清理页面资源缓存，以及超过 7 天的 `logs/startup.log.previous`。当前启动日志、数据库、项目记录、引擎会话、模型配置、API Key 和界面偏好不属于缓存。任务正在运行或文件正在提交时，Core 拒绝清理。

项目列表或项目内名称旁的 **⋯ → 重置项目**保留项目名称及工作目录，清空问题划分、所有阶段对话、报告、纠偏、消息、运行、事件、Agent 绑定与上下文、项目记忆和界面草稿。操作前显示范围与数量，一次确认后回到赛题输入页。原始赛题、附件及磁盘成果默认保留。账户 Token 活动由独立账本保存，清缓存、删除对话、移除或重置项目均保留用量与日期；详见 [Token 活动保存与恢复](33-token-activity.md)。

可勾选**同时删除 NEXIOM 生成的成果文件**，展开清单后输入完整项目名称确认。可清理文件必须有创建记录且当前内容哈希匹配；原始附件、隐藏文件、依赖目录、符号链接、目录联接、硬链接和无法验证的文件不自动删除。超过 64 MB 的单个成果也保留。清单或项目内容变化后，旧确认失效，需要重新核对。

成果来源记录位于 `.nexiom/generated-files.json`，登记本版本之后的原生文件新增事件、可视化素材修订及图片换色导出。经普通终端命令创建、早期版本生成、登记失败或用户修改过的文件可能不在可清理清单中；不会凭文件名或扩展名猜测归属。保留磁盘成果时，可视化工作台仍能读取这些素材。

## 数据一致性与恢复

重置在 Core 内同步执行，拦截运行中的项目以及正在提交的文件写入。原项目镜像、记忆及勾选的成果文件先按逐文件清单移到项目内的 `.nexiom/.reset-<id>`，不递归删除工作文件夹。Core 数据目录的 `reset-journals/<id>.json` 记录暂存映射。

SQLite 事务清除项目内容并写入提交标记，同时原子写入新的 `.nexiom/project.json`。失败时回滚数据库并恢复暂存文件；启动时在写出任何项目镜像前处理未完成的日志：未提交则恢复，已提交则完成暂存清理。暂存文件不能释放时会提示下次启动重试，不把项目重置成功等同于所有磁盘文件已释放。所有路径逐级检查，拒绝根目录与链接重定向。

重置与现有**从 NEXIOM 中移除**保持独立：移除仍保存可恢复记录，重新选择文件夹可恢复；重置会同时更新本机与文件夹中的记录，重新打开不会找回旧进度。底层引擎旧会话文件不作为缓存删除；重置解除其绑定，后续任务从新上下文开始。

## 验证

`tests/cleanup.test.mjs` 覆盖两处持久化清理、附件与其他项目隔离、来源与哈希校验、确认名称、旧预览失效、运行中拦截、镜像身份冲突、文件暂存失败、事务提交前后中断恢复、缓存空间统计与目录联接防护。界面验收使用独立开发数据目录，不访问实际赛题。
