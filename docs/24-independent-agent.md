# 独立 Agent 运行边界

版本：0.4.2，2026-09-19。

## 用户要求与问题来源

NEXIOM 必须独立配置 API Key，独立输入输出，并拥有自己的工作区、提示词和聊天。用户允许采用 Claude Code 内核，但没有要求读取个人 Codex 配置，也不需要接触内部目录和缓存。

旧版默认创建“本机 Codex 配置”，引擎进程继承宿主环境。结果不只是使用同一个模型：引擎还可能读到个人 Codex 全局指令、认证和会话目录。因此问候出现“小co”、新聊天进入 Codex 最近列表，属于隔离设计错误。

“分析摘要”来自引擎 reasoning 事件的折叠显示，不是用户执行的任务步骤。当前聊天界面不再展示这些事件，保留回复、工具动作、错误和运行状态。

## 0.4.2 的边界

- 新安装只有待配置的 NEXIOM API 供应商，用户填写地址、API Key 和模型，不借用个人登录或环境中的模型密钥。
- 桌面密钥保存在 NEXIOM 自己的加密密钥库中；浏览器开发模式只在核心内存中保存。
- 引擎的配置目录、会话存储和用户目录位于 NEXIOM 数据目录内部，子进程清理继承的个人 Agent 配置变量。
- NEXIOM 明确提供自己的 Agent 指令，不自动注入个人全局提示词、祖先目录的 AGENTS 文档或其他客户端的技能。
- 当前项目入口只允许“选择赛题工作文件夹”；所选目录直接成为项目根目录，NEXIOM 不另建或移动工作目录。
- 模型接口目前支持 Responses；独立运行不等于同时支持所有厂商原生协议。

当前内核仍为随应用分发的 Codex 开源组件。更换 Claude Code 内核属于另一个适配工作；NEXIOM 的独立配置和存储不再依赖个人 Codex 客户端。

## 升级处理

升级保留项目、问题、聊天展示、运行记录、显式填写的 Responses 供应商与密钥。删除旧的本机 Codex 配置，清理旧的引擎会话关联和上下文统计；下一次发送启动 NEXIOM 专属会话，不读取旧 Codex 线程。旧聊天仍可查看，但不会自动作为模型上下文重放，以免把污染的提示词重新带入。

迁移只针对 NEXIOM 自己的数据，不删除或修改用户 Codex 中已经出现的历史聊天。旧版进程必须先从托盘退出，再打开新版；单纯关闭窗口不会停止后台旧版。

## 验证边界

自动测试检查配置默认值、迁移幂等、旧会话失效、独立凭证和运行目录。内置引擎对本地可控 Responses 接口的集成测试检查实际请求是否泄漏外部指令和凭证，并检查会话落盘位置。桌面交互验收检查首次配置、供应商保存、未配置时的阻断、正常回复和无“分析摘要”显示。

本地测试接口不等同于真实厂商模型。用户提供自己的 API 配置后，才可验证该服务的实际模型质量与工具兼容性。
