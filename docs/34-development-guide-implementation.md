# NEXIOM 0.7.0 开发指南实现说明

本版本依据《Nexiom开发指南.docx》落实研读、建模、检验、反馈、最终确认和可视化之间的工作流，并补充项目工具与界面交互。原文中尚未给出标准的论文写作、创新性评价、机械套模识别和绘图模板扩展，保留为后续产品设计事项。

## 从哪里开始

打开赛题文件夹，在 NEXIOM 设置中配置自己的 Responses 兼容模型供应商。完成赛题研读与附件分析后，“开始建模”和“模型检验”自动按研读报告中的小问生成分区。先进行初步分析，再选择 AI 独立建模或协同 AI 建模。每条路线完成方案后可独立检验、保存反馈并协同修订。最后在“项目总览”逐问选择已检验版本。

“文件”菜单提供项目终端、项目插件、Git 与工作树；项目菜单可以归档和恢复项目。程序默认拥有完全访问权限。联网开关控制文献检索工具，不阻断终端或执行程序的网络连接。

## 成果与状态存在哪里

```text
项目目录/
  .nexiom/workflow.json                 工作流状态、版本、核对项和依赖决定
  .nexiom/plugins.json                  启用的项目插件与资料
  reading/赛题研读报告.md
  reading/annotations/                 带批注的 PDF 副本
  reading/research/                    分类研究记录
  attachments/reports/                 逐附件分析报告
  modeling/shared/                     各问共享进展与依赖决定
  modeling/问题N/independent/           AI 独立路线及该路线的协同修订
  modeling/问题N/collaborative/         协同 AI 路线
  modeling/问题N/<路线>/feedback/       检验反馈文件
  validation/问题N/<路线>/<版本>/       独立检验材料包和 review.md
  modeling/final/最终模型.md
  modeling/final/versions/              历史确认汇总
  outputs/visual-design/modeling/       建模方案图表
  outputs/visual-design/paper/          论文论述图表
```

每次新建分析、建模、检验或修订任务使用新目录；同一协同讨论的续接可修改该轮目录。方案和相关文件的摘要与检验版本绑定。重新研读、方案变更、新反馈或新建修订任务都会使受影响的确认失效。旧最终汇总会注明待重新确认，应用拒绝将其当作当前最终模型导出；已导出的独立文档仍是当时的快照。

工作流 JSON 校验结构后再使用，以临时文件加重命名保存。关联成果的会话禁止单独删除、移走或分叉，避免破坏检验关系；历史普通会话继续使用原有管理方式。项目重置把工作流状态纳入原有预览与事务恢复机制。

## 当前边界

- 本次确定性集成测试覆盖真实核心服务与文件写入，模型回答由测试执行器提供。未使用用户个人 Codex 凭据，也未对真实付费模型进行整题建模质量验收。配置供应商后仍需要实际赛题评估模型的推理、求解和文献真实性。
- “独立检验”隔离的是会话上下文与准备的材料。由于指南要求完全访问权限，它不是操作系统级沙箱；提示中的材料约束不能当成文件访问安全边界。
- 终端是持久命令行会话，支持普通命令和输出；不提供 PTY 全屏交互应用。外部 Agent 不会自动实时感知人的终端操作。
- 插件目前是项目级领域说明和模型库资料包，支持 JSON 导入与启停；没有通用插件市场或任意 MCP 插件安装器。Git 工具要求本机有 Git，创建工作树要求仓库至少已有一次提交。
- 原句批注面板由报告引用块生成。未实现 Agent 自动将每条引用定位为原 PDF 的坐标高亮；PDF 的手动批注可保存。
- 术语、风险、清洗决策、模型组成和检验观点由模型依照工作流生成。结构约束和文件就绪检查不能保证内容正确，仍需人审核。
- Word 公式通过 MathML 转为可编辑 OMML，常见分式、上下标、根式、上下限、重音和矩阵已处理；复杂自定义宏或特殊排版不保证与 TeX 完全一致。图片导出支持项目内 PNG/JPEG/GIF/BMP；SVG、远程图片须先转为本地常见位图，不会悄悄省略。
- 语义编辑支持当前已有的条形图、折线图、散点图和结构图，不等同于任意图片的 Illustrator 编辑。论文支线需要用户明确选择并确认已有 Markdown 初稿；未实现完整论文审稿及自动发布流程。
- 原指南“论文写作”“后端设计”未给出具体新增要求，创新性、机械套模及更丰富的绘图思考标准也明确留待补充。本版保留现有论文 Agent 与后端基础，不虚构这些标准。

## 验收记录

0.7.7 将总览的终态标识移至状态文字旁，非运行状态的主图标始终使用导航同一份板块图标定义，避免把赛题研读的书本替换为勾选。运行中的步骤动画和七色规则保持不变。浏览器核对书本 SVG 与导航一致，并验证四种终态保留板块图标。

0.7.6 根据反馈取消总览独立配色，直接复用原有七种 Agent 动作颜色，方块、状态文字和运行卡片边框均跟随当前动作。未开始图标沿用对应板块的既有标识颜色，完成和其他终态图标规则不变，不增加外观设置预览项。

0.7.5 调整总览状态呈现：运行时才挂载方块动画；未开始显示板块图标，完成显示勾选，失败、停止和中断显示对应结果图标。八张卡片采用单独定义的配色，与 Agent 动作颜色和外观预览分离；最终模型按人工确认状态显示，不把等待确认当成后台运行。删除最近任务列表及更新期间的构建提示文字。浏览器验证深浅主题、七环节同时运行的独立动画颜色，以及经 SSE 刷新的四种终态切换，确认终态和待机卡片不含 loading；总览状态逻辑测试通过。

0.7.2 界面调整：总览集中显示七个环节的最新任务状态、运行数量、耗时、最近任务与最终模型确认入口。状态由现有快照更新驱动，复用方块动画，运行时播放，终态暂停；“最近任务完成”不代表整个环节完成。所有工作板块复用统一标题组件，包含彩色图标、项目名和板块名；导入、进度与报告页面同样保留标题。讨论输入框空内容约 48px，随输入增高和收回，下拉菜单适配深浅主题与长文件名。

浏览器验收覆盖八个板块、深浅主题、1440px 和 1000px 窗口、讨论框伸缩、长初稿文件名选择及最终模型入口。隔离验收项目通过真实 SSE 通知触发快照刷新，以浏览器内注入的运行/完成状态验证总览无需重载即可更新文字、颜色和动画；此项未调用实际模型。

0.7.2 类型检查、构建与 Windows 打包通过。全量 252 项测试首轮 250 通过、1 跳过、1 失败；失败为流式保存测试的异步读取占用 Windows 文件句柄，与原子重命名冲突。测试改为关闭读取句柄后再让出执行权，保留全部保存时序断言；该项与新增总览状态测试复测均通过。便携包位于 `release/NEXIOM-0.7.2-win-x64/NEXIOM.exe`。

类型检查通过；自动化全量测试 251 项，250 通过、1 项因 Windows 环境不能创建文件符号链接而跳过、0 失败。最后调整后相关集成测试再次通过。新增集成覆盖自动分问、初步分析门槛、检验材料隔离、反馈与修订隔离、版本失效、最终确认、Word/HTML 导出、PDF 副本、终端项目归属、插件上下文和中文加粗修复。

浏览器实测覆盖建模与检验切换、问题和路线切换、依赖保存、核对清单、原文批注排版、PDF 保存、选中文字进入草稿、项目终端及主题菜单。Word/PDF 样例经过实际渲染，检查了中文、表格、图片与公式。测试产物保存在被忽略的 output/ 目录，不进入用户项目。

Windows x64 便携包已通过构建与打包，路径为 release/NEXIOM-0.7.0-win-x64/NEXIOM.exe。使用独立用户数据目录实际启动打包程序，确认渲染进程与核心就绪，并通过真实桌面 IPC 导出包含公式、表格和图片的 Word/PDF；PDF 返回 pdfReady=true，已检查成品页面。Vite 仍提示部分包体大于 500 KB，这是后续性能优化项。
