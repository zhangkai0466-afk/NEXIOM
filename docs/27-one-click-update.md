# NEXIOM 0.6.18–0.6.21：一键源码更新

日期：2026-09-20。

## 问题

NEXIOM 关闭窗口后仍在系统托盘运行，并持有单实例锁。最初版本的按钮只会切换到桌面快捷方式已经指向的新版，不能构建 Codex 刚修改的源码；0.6.20 的后台安装器又可能在应用退出时被系统提前终止，造成程序退出后没有重新打开。0.6.21 改为由应用自身完成可靠重启。

## 交互

两层侧栏底部的账户入口右侧保留独立蓝色圆形更新按钮。点击后按钮旋转，并显示“正在构建并安装最新修改，请稍候…”。任何项目仍有任务运行时按钮禁用，避免中断工作。源码目录、Node.js/npm、构建或安装出现问题时，当前实例不会退出，并在按钮上方显示具体错误。

## 切换流程

按钮从当前发布目录反查 `D:\NEXIOM` 源码根目录，运行 TypeScript/Vite 构建并把完整桌面程序生成到受约束的临时目录。构建成功后，当前实例先把桌面快捷方式切到这个完整目录，再调用 Electron 自身的 relaunch 机制；随后沿用现有退出链路优雅停止 Core 并退出。新实例完成启动后清理旧目录。浏览器开发预览没有桌面主进程，点击同一位置时只重新载入当前页面。

由于 Windows 会锁定正在运行的 EXE/DLL，构建期间会短暂存在当前版和临时新版两份文件。新实例完成启动后会删除旧版本与遗留的更新目录，稳定状态只保留当前运行目录；用户数据、聊天、设置和工作区均不在发布目录中。

## 发布目录清理

Windows 会锁定正在运行的 `NEXIOM.exe` 和相关 DLL，所以不能在旧实例运行时直接覆盖其目录。NEXIOM 使用短暂的双版本切换：先完整生成新版，切换并完成新版首次启动动画后，再由新版删除同一 `release` 根目录中的旧版本号目录、旧更新目录和受控回退目录。清理只处理受约束名称的直接子目录，不跟随符号链接，不删除当前运行目录或无关目录；失败只写入启动日志，不影响应用运行。

项目、对话、API Key 和设置不保存在发布目录中，因此删除旧程序目录不会删除用户数据。代价是切换前会短暂占用两份空间，切换成功后回到一份；旧二进制不会再保留用于手工回退。
