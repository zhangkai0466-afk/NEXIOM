# 赛题项目与项目内导航设计

日期：2026-09-20。状态：两层侧栏、四项可展开对话导航和本地账户已纳入应用；赛题研读已改为“输入赛题—自主分析—结构化报告—人工纠偏”的专用工作台，附件分析已改为“输入附件—workflow 分析—按附件报告—独立纠偏”的专用工作台，检查交付保留独立聊天框。项目总览已撤销对话，后续作为调度与成果查看界面，具体结构仍待用户定制。

本设计落实用户对上一版导航草案的修正，关联 [建模伙伴功能](22-modeling-partner-functional-design.md)。[可点击导航草案](prototypes/modeling-navigation.html) 保留为交互参考；本轮工作对象已转为实际桌面应用，不能用草案的浏览器检查结果代替桌面实现验收。

“随便聊聊”支持多个独立对话：侧栏标题旁的“＋”直接新建对话，列表支持切换、重命名、归档与删除。打开入口恢复上次选择，不再强制重命名已有对话；旧单会话的记录保留。删除当前对话后选中剩余的未归档对话，删空后显示新建入口。运行中统一显示“思考中”与累计秒数。

侧栏不再重复显示顶部“添加”按钮，添加项目使用“项目”标题旁的“＋”。“随便聊聊”标题仅在悬停时加深，其列表去掉缩进竖线和逐项图标；具体选中的对话仍有选中背景。两个分组均以高度、位移和透明度过渡展开或收起，折叠内容退出键盘导航，减少动态效果时立即切换。新对话欢迎语为“聊点什么？”，欢迎页及侧栏字标使用无底色 N 标志；侧栏英文采用 OpenAI Sans Semibold，来源记录在字体目录。

## 1. 本轮明确决定

- 初始侧栏用于添加和列出“赛题项目”，每个项目对应一个赛题解题的工作区文件夹。
- 添加项目后，点击该项目，左侧通过动画切换为该项目内的多个建模维度入口。
- “数据分析”改名为“附件分析”，“计算实验”改名为“模型检验”；本轮进一步将“建模方案”入口改名为“开始建模”。数学内容中的“建模方案”仍是正常术语。
- “开始建模”的入口图标采用用户提供的 [二级图标.svg](C:/Users/zhuka/Downloads/二级图标.svg)。用户消息中的“二级图表.svg”按实际提供文件解析。
- 开始建模、模型检验、图表设计、论文写作四项可展开，并在各自下方添加和选择针对具体问题的对话；用户要求这些对话独立又连贯。
- 删除界面中的所有说明性小字，包括添加项目弹窗的介绍、示例占位、原型边界提示及侧栏说明。保留操作所需的字段标签、按钮名称与错误反馈；文档仍记录原型边界。
- 用户接受侧栏方向，明确拒绝上一版点击入口后出现的内容界面。旧版内容卡片、页面布局、右侧伙伴讨论面板和公共分问筛选不作为已接受方案延续；所有内容页面重新设计。
- 用户已授权将该导航正式接入 NEXIOM；选中对话时使用已有真实对话能力。赛题研读和附件分析使用各自的专用结构化工作台，并把底层持久化线程仅用于对应的分析、报告与纠偏；检查交付有自己的聊天框；项目总览不使用对话，后续承载总调度、成果查看与论文 PDF 成品查看。
- 对话列表提供清晰的“重命名”操作，修改显示名称并持久保存，不新建对话，不改变问题、维度或历史记录。
- 两层侧栏底部只保留账户栏目，显示头像和昵称；点击展开菜单并进入设置。暂不添加“协作经验”“项目文件”入口。
- 设置新增账户页，支持设置头像和昵称。用户已确认 token 用量按日期显示为蓝色小方块，颜色越深表示该日已记录用量越多。

以上授权针对导航、对话组织和账户功能，不表示九项建模能力已整体交付。本轮实际验证范围在第 8 节单独记录。

## 2. 两层侧栏

```text
赛题项目列表                   某一赛题项目内

NEXIOM                         ← 赛题项目
添加赛题项目                   当前赛题项目名称

赛题项目 A                     项目总览
赛题项目 B                     赛题研读
……                             附件分析
                               ▾ 开始建模       ＋
                                 第一问
                                 第二问
点击某个项目 ──动画进入──→      模型检验
             ←─返回──────      图表设计
                               论文写作
                               检查交付

头像  昵称                     头像  昵称
```

初始侧栏以项目列表为主。进入项目后，该侧栏位置整体切换为当前项目的导航，不在项目树下继续展开一整组功能。顶部提供“所有赛题”返回按钮并显示当前项目名称；返回后可继续添加或选择其他项目。

项目内八个入口顺序为：项目总览、赛题研读、附件分析、开始建模、模型检验、图表设计、论文写作、检查交付。它们是同一项目的不同工作维度，不是必须依次完成的关卡；点击入口不自动创建 Agent、发起计算或判定该阶段完成。

开始建模、模型检验、图表设计、论文写作采用相同的展开交互：入口可折叠下方的对话列表，通过添加按钮创建对话，再点击列表项选中。折叠只收起列表，不删除对话。上图只展开开始建模作为示意，并不表示其他三项不能展开。

赛题研读、附件分析、检查交付三个入口都不增加下拉列表或添加对话按钮。赛题研读进入专用工作台：入口只保留赛题文件选择，不提供正文输入或复制粘贴；已选文件形成简洁列表，点击 PDF 后在右侧展开内置查看器，用户明确点击后开始自主分析。结果按报告目录浏览，至少包含原题逐句研读、名词与口径、每个小问、依赖关系、陷阱、待核验项和交付清单，并按固定标题和表格字段生成。报告页可返回输入页。人工纠偏绑定当前报告板块或当前 PDF 原题文件，各自保留记录与草稿；栏宽通过分隔线调整，窄窗口下排到正文之后而不覆盖正文。PDF 可在中央工作区直接查看，现阶段批注精度到文件，不伪装成页码坐标或划词批注。附件分析进入独立的文件优先工作台：初始页只保留一个居中的附件导入入口，不显示说明卡、附件勾选列表或额外的开始按钮；导入成功后，系统立即按读取完整性、内容结构、数据质量、跨附件关系、建模作用、风险与建议动作的 workflow 逐个形成报告。报告页左侧按附件切换，右侧纠偏历史和草稿绑定当前附件，提交纠偏只生成该附件的新报告版本，其他附件保持原报告。检查交付仍打开单一对话。三者底层均在每个项目首次进入时建立持久化线程，后续点击、切换项目和重启继续使用已提交的状态。项目总览不建立对话，当前仅保留无输入框的占位界面，等待后续调度与成果查看设计。

列表中的对话通过条目菜单选择“重命名”，编辑并保存名称。重命名针对打开菜单的条目，不能误改当前选中的另一条对话；取消操作保留原名。问题关联、消息、草稿和正在运行的任务均继续使用原对话身份。

添加对话弹窗只含“问题”和“对话名称”两个字段。问题为必选，能够选取已有问题或登记新问题；对话名称可选，留空时使用问题名称。弹窗不添加说明性小字，必要的缺失字段错误反馈保留。同一问题可以在不同维度拥有对话；对话名称是显示名，不能用它代替问题或会话身份。

“附件分析”名称覆盖赛题所附的各类材料，不预设附件全部是表格数据。“模型检验”作为新入口名，不表示产品取消编程、求解或实验能力；这些能力如何进入具体页面，留待后续功能设计。

账户栏目在两层侧栏均可使用。设置通过账户菜单进入；此前对“协作经验”“项目文件”辅助入口的建议已被本轮决定取代。项目记忆与文件操作的既有底层能力不因此被删除。

## 3. 添加赛题项目

目标行为：用户通过“添加赛题项目”选择一个解题工作区文件夹，将其作为赛题项目加入列表，然后点击项目进入项目内导航。添加工作区与导入赛题附件是不同操作；添加项目本身不启动文件解析或求解。

本轮接入要求：

- 初始项目名称使用所选文件夹名称；项目重命名不属于本轮新增能力。
- 记录项目身份及其工作区路径；再次添加同一文件夹时定位已有项目，避免重复登记。
- 取消文件夹选择则保持原列表；路径不存在或不可访问时说明原因，不创建看似可用的项目。
- 空列表仍保留明确的添加入口；返回项目列表不删除工作区、关闭项目任务或清空项目状态。

桌面应用使用系统目录选择器登记真实工作区，并将项目保存在本地核心中。浏览器开发预览只能创建应用管理的项目文件夹，不能冒充原生任意目录绑定。独立 HTML 草案仍只演示选择目录和添加列表项，不承担持久化。

## 4. 过渡与状态

进入项目时，项目列表向左退出，项目内导航从右侧进入；返回列表时反向过渡。建议时长约 240 毫秒，动画限于侧栏内部，避免整个窗口随之移动。尊重系统的减少动态效果设置，改为无位移或即时切换。

动画完成后，应让键盘用户能继续操作新一层导航；不让移出视野的按钮继续获得焦点。连续点击不叠加过渡，始终以最终选择的项目为准。

每个项目独立保存当前入口和必要的工作状态。同一项目各工作维度共享该项目的决定与成果；切换项目时不把其他项目的假设、文件、草稿或运行状态带入。返回或切换侧栏不隐含执行授权，也不自动中断已经允许的任务。

对话列表的展开状态、当前维度和选中的对话按项目分别记录，返回项目后恢复。桌面集成需要保存导航偏好，并由本地核心持久化项目、问题、对话与消息。旧版本的会话归入其项目的“开始建模”，保留会话身份和历史，不按相同标题自动合并问题。

## 5. 按问题组织对话

本轮正式接入分别标识项目、问题、工作维度与对话：

| 标识 | 作用 | 关系 |
| --- | --- | --- |
| `projectId` | 赛题项目身份 | 隔离不同赛题工作区及其状态 |
| `questionId` | 项目内问题身份 | 按问题添加的对话跨四个可展开维度使用同一个 ID；项目级单一对话为空 |
| `stageId` | 当前工作维度 | 区分全部八个入口，四个可展开维度可有多个对话，其余四个维度在每个项目内各有一个对话 |
| `threadId` | 单个对话身份 | 关联项目、维度及适用的问题；对话自身内容与草稿独立，重命名不改变身份 |

“独立又连贯”包含两个要求。每个对话有自己的记录、草稿和当前任务，不能因切换维度而覆盖另一对话。与此同时，同项目已采用的条件、经确认的成果及其依赖可以被相关问题和维度引用。例如，第二问的模型检验对话可定位第二问开始建模时采用的假设与模型版本，图表和论文对话可引用相应结果版本。

共享通过带来源、版本和适用范围的项目事实与成果关联完成，不能把所有对话全文串接到每次请求中，也不能把同名对话自动认定为同一问题。前问条件是否被后问继承仍须有明确依据。问题改名应保持原 ID；具体的上下文选择、修改传播和依赖复核留待后续功能设计与实现。

本轮接入问题与维度元数据，复用真实会话、消息和已有项目记忆能力。问题 ID 让同题的对话具有明确关联，但不会自动提取已采用假设、判断跨问继承、传播成果或复核依赖；这些语义能力仍待设计与实现。

## 6. 本地账户与 token 用量

账户页参考用户要求的 Codex 账户设置布局，提供头像、昵称和按日用量。头像和昵称是 NEXIOM 的本地个人资料，在本地核心持久化；不代表已登录新的云端账户，不新增虚构的邮箱、订阅、余额或套餐信息。模型认证仍由现有供应商设置负责。

用量取自 NEXIOM 实际保存的每次 Agent 运行记录，按本机日期汇总为蓝色方块日历。每天的数值为有效运行用量中的输入 token 与输出 token 之和，缓存输入已包含在输入中，不能重复相加；同一运行只计一次。不以会话累计上下文或重复事件代替本次运行消费。

没有收到或无法解析的用量保留为未知，不生成演示数据或把未知记录称为零消耗。页面仅反映本机 NEXIOM 已记录的使用情况，不表示供应商账户全部历史、剩余额度或最终账单。必要的统计范围与缺失记录提示属于数值含义，不增加泛泛的介绍小字。

## 8. 验证范围与记录
