# NEXIOM 架构设计索引

版本：0.6.25，2026-09-22，共同开发的起点。历史草案保留；当前独立性以 [独立 Agent 运行边界](24-independent-agent.md) 为准。早期采用本机 Codex 配置的技术实现已被用户明确否定，不能视为当前要求。

2026-09-19 阶段更新：用户明确当前 NEXIOM 尚不能承担完整实际建模工作，领域功能继续设计、逐步实现和验证。最新授权将确认的导航、按问题组织对话和本地账户正式接入应用。当前设计入口为 [建模伙伴功能设计草案](22-modeling-partner-functional-design.md)；已有桌面、执行基础、多模型供应商配置和本轮导航不表示完整工作能力已经具备。

NEXIOM 是面向全国大学生数学建模竞赛的桌面 Agent。项目入口只允许选择一个具体的赛题工作文件夹，拒绝磁盘根目录等无效路径；选择后直接进入项目，工作文件、附件、记忆与可迁移的项目记录都以该目录为根。开始建模、模型检验、图表设计、论文写作四项可展开并按问题添加对话；会话菜单支持重命名、标记未读、归档、永久删除、跨项目移动、复制、分叉和在独立窗口打开。赛题研读使用可输入题面、自主分析、分板块查看并人工纠偏的专用工作台；附件分析初始页只显示居中的导入入口，导入后自动按固定 workflow 分析，并按附件查看报告和独立纠偏；检查交付直接打开一个独立、持久化的聊天框。项目总览不再提供对话，后续将作为项目调度、成果与论文成品查看界面，具体结构待用户确定，详见 [工作区导航设计](23-modeling-workspace-navigation.md)。底部保留账户入口及独立的一键更新按钮；账户设置支持本地头像、昵称与按日蓝色方块 token 用量。

当前图表设计已接入真实资源库与工具，详情见 [图表设计与资源库](25-visual-design-integration.md)。旧文档中图表专用首页留空的描述已由 0.5.0 取代。

## 现场检查

初次设计前，`D:\NEXIOM` 有 27 个文件：24 个品牌图标文件（SVG、PNG、ICO），以及 `tools/` 中 3 个 PowerShell 图标导出脚本。当时没有应用代码、依赖清单、测试、架构文档或 Git 仓库。后续已开始基础搭建，当前实现范围见基础版说明。

已有资产保持原样。品牌目录存在多个候选图标，当前没有证据说明哪一个是正式版本。本地没有发现 `AGENTS.md` 文件；遵循本次对话提供的约定，协作者名为“小co”，这不自动决定产品内 Agent 的名称。

## 仍需共同决定

1. 模型接入的商业形态：当前使用用户独立填写的 Responses 兼容 API Key，是否提供产品托管服务仍未决定。不再接入个人 Codex 登录。
2. 首版交付物是否必须可编辑 DOCX，以及是否必须支持 MATLAB。这两个选择直接影响开发路线和安装体积。
3. 操作系统范围、开发人数、预算和目标交付日期。未明确前，路线以验收门槛排序，不给无依据的工期承诺。

可先评审产品流程和领域结构；P0 结束前必须确定模型接入、平台及文档出口，随后形成 v0.2 架构基线。
