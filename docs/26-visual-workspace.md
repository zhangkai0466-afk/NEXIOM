# 可视化工作台

## 设计与归档

Agent 在建模、图表设计、论文写作阶段都可调用原生可视化工具。建模过程素材用于说明方法、变量关系和初步结果；论文论述素材用于支撑具体章节的比较、论据和结论。

可视化设计任务在项目对话中发起，设计用途由用户与 Agent 在对话中确定。工作台只负责统一汇集已生成素材、调色、结构调整和保存修订，不提供新建设计入口或设计用途弹窗。

执行模式下由 Agent 调用 `ensure_visual_libraries` 创建目录，或由 `create_visual_asset` 在生成第一张图时创建：

```text
outputs/visual-design/
  modeling/       # 建模过程可视化素材
  paper/          # 论文论述可视化素材
```

这两类只影响设计目的和归档位置。工作台在一个列表中展示所有已登记的 Agent 素材，共用调色和结构调整功能。浏览工作台本身不会创建素材目录。

每张素材必须记录用途，以及 1 至 32 个实际存在的项目资料文件。概念图可引用 Agent 在项目中整理的推导说明；数值图必须基于真实数据，不能以参考图库或演示数据替代项目结果。

## 编辑行为

- 调色按语义元素操作。分组条形图以 D/E/F 为横轴类别，以 A/B/C 为数据系列；选择 A 后修改其配色，所有 A 的柱形和 A 的图例同步变化，B/C 不受影响。
- 调整修改元素结构，支持拖动图例、标题、轴标签、绘图区、注释和结构图节点，也可输入水平/垂直位置。结构图连线跟随节点变化。
- 所有预览从图定义重新生成，不修改位图像素；工作台不会修改系列数据、类别、文本内容和节点关系。
- 撤销、重做及已保存版本对比覆盖配色与位置修改。切换项目内对话会保留编辑状态；切换素材有未保存提示。
- 点击“确认保存入库”后生成新修订，同时写入图定义、可独立运行的绘图源码和 SVG。旧修订保留，版本冲突时拒绝覆盖。

每张图的目录结构：

```text
modeling/<asset-id>/
  current.json
  rev-1/
    meta.json
    figure.json
    render.mjs
    figure.svg
  rev-2/
    ...
```

`render.mjs` 内含实际系列色值与布局坐标，无需 NEXIOM 依赖即可用 Node 重现 SVG：

```powershell
node render.mjs reproduced.svg
```

## Agent 工具

| 工具 | 行为 | 模式 |
| --- | --- | --- |
| `ensure_visual_libraries` | 创建两个素材目录 | 执行 |
| `list_visual_assets` | 统一列出两类素材及来源 | 规划 / 执行 |
| `get_visual_asset` | 读取数据、元素及源码位置 | 规划 / 执行 |
| `create_visual_asset` | 生成、登记图像和源码 | 执行 |

这些工具不需要 Python 或 MCP。原 Python 模板工具仍可由图表设计 Agent 用作绘图能力，原色库继续提供可选颜色，参考图库不接入工作台。

## 绘图约束如何生效

### PS-FRAME-001：完整矩形坐标框

二维直角坐标数据图必须使用完整的左、下、上、右四边矩形框，围住数据绘图区；四边采用统一的细线样式，上、右边默认不重复刻度和标签，真实的次坐标轴保留自身刻度。边框和辅助线位于数据图形下方。此规则不用于结构图、饼图、极坐标、三维图及连续色条。

可编辑分组条形图、折线图和散点图由 `renderVisualFigure` 固定绘制完整矩形，无需 Agent 再选择或启用。移动、缩放绘图区时边框同步变化；预览、保存 SVG 和独立 `render.mjs` 使用同一个渲染函数。历史素材在工作台重新打开时按新规则预览，历史文件不自动覆盖；保存新修订后才更新磁盘上的 SVG 和源码。

Python 模板在导出前恢复四边，并在 Matplotlib 实际绘制后检查边框端点、可见性、样式、图层与重复刻度。静态源码检查只将该规则标为 `pending_render`；正式输出检查读取本次渲染进程返回的规则结果，缺少检查或检查失败时拒绝标记为可交付。检查记录也保存在图像旁的 `.quality.json` 中。

### 四层执行链

1. Agent 指令与工具说明：让模型理解用途、来源、配色和外观原则。这层负责引导，不能单独保证结果。
2. 工具参数与入库校验：用结构化 schema 检查图种、数据长度、颜色格式和布局范围；核实来源路径存在。工作台保存时还会拒绝修改数据、文字或元素关系。
3. 确定性绘图：Agent 提交数据和图定义，由固定渲染器生成 SVG；矩形框等硬性外观由代码执行。Python 模板链使用公共模板、代码质量检查与导出前排版处理。
4. 验证：自动测试检查矩形边框、绘图区位置、图层顺序和独立源码重现；实际截图用于检查可读性。测试保证被覆盖的行为，不代表系统自动判断了每一张图的科学性或审美质量。

来源文件存在不等于数据或论述一定正确；配色理由、图种是否合适等仍需要 Agent 核对资料。原 Python 模板的其他外观规范尚未全部迁移到可编辑 SVG 渲染器，不能将“提示词提到规则”视为“代码已强制执行”。直接用终端自行绘制且未走上述工具的图片也不受这条完整执行链保证。

## 当前支持范围

当前可直接编辑通过新工具创建的分组条形图、类别折线图、散点图及结构图。Agent 根据生成时的图种、数据系列和标签记录元素对应关系，工作台通过这些信息定位元素；这不是对任意位图做语义识别。

既有 Python 模板图片、历史 PNG 和用户导入的图片不会被自动转为可编辑素材。62 个模板的源码配置、数值横轴、区间、多面板和色标等语义尚未全部适配，不能将它们简单转换为四类图而改变图意。新工作台只显示有完整图定义及 Agent 登记信息的素材。
