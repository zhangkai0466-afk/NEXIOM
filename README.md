## 启动

Windows 便携版首次打开 `release/NEXIOM-0.6.21-win-x64/NEXIOM.exe`，或使用桌面的 NEXIOM 快捷方式。之后 Codex 修改完源码，直接点击侧栏账户入口旁的更新按钮；NEXIOM 会自动构建、切换运行目录并重新打开。需保留源码目录及 Node.js/npm 环境；右上角关闭按钮只会隐藏窗口。

重新创建快捷方式：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/create-shortcut.ps1`。快捷方式使用系统桌面位置，目标版本从 package.json 读取。

EXE 是桌面入口；项目管理、持久化和工具执行分别由独立 Core 与 Codex 原生进程承担。当前项目文件、记忆以及可迁移的项目记录都在项目目录中；本机应用数据仍保存工作索引和运行时数据。详见 [项目级 Agent 的实现边界](docs/12-project-agent-positioning.md)。

启动日志位于 `%APPDATA%\NEXIOM\logs\startup.log`（配置了 `NEXIOM_USER_DATA_DIR` 时跟随该目录）。界面加载失败或崩溃会提供重新载入及日志入口；日志只记录生命周期元数据，不记录任务正文、密钥或命令内容。

源码开发：

需要 Node.js 24+、npm；首次安装需要网络。

```powershell
npm install
npm run dev
```

开发预览地址以终端输出为准，默认 `http://127.0.0.1:5173`。浏览器预览连接真实的独立本地核心，数据保存在 `.local/browser/`。

```powershell
npm run desktop
```

该命令构建并打开 Electron 桌面窗口。桌面数据位于 Electron 用户数据目录下的 `workspace/`，与浏览器开发数据隔离。桌面支持通过系统文件夹选择器打开已有项目；浏览器只能创建应用管理的本地项目和导入选定附件。

## 当前能力

- 选择并管理本地赛题工作文件夹；创建、切换、搜索、重命名、标记未读、归档、删除、移动、复制、分叉会话，并可在新窗口打开会话。
- 赛题研读专用工作台：入口只选择赛题文件，不提供正文粘贴框；点击已选 PDF 时在右侧展开内置查看器，确认后自主生成结构化报告。报告按固定的标题、表格字段和状态枚举浏览原题逐句、名词口径、问题一至问题 N、问题依赖、陷阱、待核验项和交付清单；每个板块拥有独立的人工纠偏记录和草稿，纠偏栏可拖动调宽且不会覆盖正文。
- 附件分析专用工作台：初始页只保留居中的附件导入入口，导入成功后自动按读取完整性、内容结构、数据质量、跨附件关系、建模作用、风险与建议动作的固定 workflow 逐个分析；报告按附件切换，每个附件拥有独立的人工纠偏记录和草稿，纠偏只更新目标附件，不重写其他附件报告。
- 会话持久化、重复提交去重、NEXIOM 私有引擎会话续接与真实工具记录。
- 暗色、浅色与跟随系统；统一 Windows 系统字体、对话字号和减少动态效果设置。
- 左侧项目导航可连续拖动调整宽度；向左越过阈值自动收起，向右受主内容最小宽度和最大宽度约束，并记住上次确认的宽度。分隔反馈使用不会越过主内容圆角的短拖柄，收展采用连续缓动；双击恢复默认宽度，也可用方向键、Home 和 End 操作。
- 全页设置：左侧分类与搜索，右侧分组设置；返回会话保留输入草稿与阅读位置，未保存配置及记忆提供离开保护。
- 原生消息增量、输出光标、Thinking Orbs 状态动画、工具记录平滑展开；向上阅读时不强制拉回底部。
- 用户审阅的项目记忆 `.nexiom/MEMORY.md`，包含版本冲突保护，下次任务重新加载。
- 上次输入/输出与缓存 token、原生上下文窗口和压缩次数；未知值不估算为精确用量。
- 对话使用统一任务流程；Agent 可在当前赛题工作区内读取、修改项目文件并运行必要程序。
- 展示 Markdown、数学公式、工具输出、文件修改、任务失败及取消状态。
- 管理多个模型供应商配置：新增、编辑、删除、启用，手动填写模型 ID，获取模型列表并检测连接；当前支持兼容 OpenAI Responses API 的服务。
- 供应商名称、地址、模型、认证方式和修订号保存在 SQLite；每个供应商的 API Key 独立保存，不进入数据库、运行快照或会话指纹。
- 桌面 API Key 使用 Electron `safeStorage` 加密后写入应用数据目录中的 `provider-secrets.enc`；界面只读取“是否已配置”，不会回显密钥。浏览器开发预览中的 Key 仅保存在本地核心内存。
- 每次 Agent 运行记录非密钥的供应商来源和运行参数；会话按这份运行身份绑定，因此从 A 切到 B 后再切回未修改的 A，可以续接 A 在 NEXIOM 内部的会话。修改供应商配置后使用新会话。
- 导入附件（单文件不超过 10 MB，不覆盖同名文件），查看文件清单。
- 文本和常见位图预览（不超过 2 MB）。PDF/DOCX 暂不预览或解析。
- SQLite 存储、独立 Core 进程、限定 IPC、单核心锁和中断状态恢复。

首次使用：从欢迎页选择一个具体的赛题工作文件夹。进入项目后，在设置中填写 NEXIOM 自己的 API 地址、API Key 和模型名称，即可直接发送任务。可随时停止任务；停止不会回滚已经产生的文件。Python 使用本机已安装环境，尚未内置科学计算环境。

NEXIOM 不再给整轮 Agent 任务设置默认 15 分钟或其他固定倒计时。任务以引擎完成、失败、用户停止或应用关闭结束；短连接请求、工具调用与进程退出的超时各自处理。旧配置中的 `timeoutMinutes` 被忽略，其他设置与项目记录保留。详见 [任务生命周期修正](docs/13-agent-lifecycle-correction.md)。

供应商的检测目前以 `GET <根地址>/models` 为主，用于验证网络、Bearer 凭证和模型列表格式；它不会向 `/responses` 发起一次真实推理，因此“检测通过”不等于所选模型的流式、工具调用和完整 Agent 回路已经验证。当前版本要求服务同时提供可访问的 `/models`；地址应填写根地址（通常以 `/v1` 结尾），不要包含 `/models` 或 `/responses`。

供应商执行时使用 Responses 协议。仅兼容 Chat Completions 的地址不能直接接入，Anthropic 和 Gemini 原生协议尚未实现。NEXIOM 启动内置引擎时使用应用专属目录和净化后的环境，仅注入本次选中的 NEXIOM 配置，不读取个人 Codex 的配置、认证、全局指令和会话。详见 [模型供应商配置中心](docs/23-model-provider-profiles.md)。

独立实验版本管理、证据图谱、PDF/DOCX 解析和论文导出尚未实现。首版是可运行的 Agent，不代表完整竞赛工作流已经交付。

赛题研读与附件分析已具备专用输入、结构化报告和人工纠偏工作台，但报告目前仍由持久化线程中的 Markdown 驱动，尚未把每条结论转成可跨工作维度引用的领域实体；项目总览与检查交付的专用内容仍待继续设计。项目总览不创建或显示对话；四维会话使用已有真实 Agent。问题身份关联不自动完成假设继承、成果传播或依赖复核。账户资料仅保存在本地；[Token 活动](docs/33-token-activity.md)独立保存并自动备份，清理或重置项目仍会保留，支持导出、合并导入及恢复 NEXIOM 本地引擎历史。累计数覆盖全部已保存日期，热力图展示最近一年；缓存输入不重复计入。它不表示供应商账户全部消费或剩余额度，缺失记录不作零消耗处理。

## 开源复用

基于 [OpenAI Codex](https://github.com/openai/codex) 的官方原生引擎 `0.154.0`，通过 app-server 协议复用工具循环、会话历史、沙箱和自动上下文压缩。固定来源为 `rust-v0.154.0`，提交 `6b9826e3aa83b1a5947db50f4332cb9c65f1b340`。此前引入的 TypeScript SDK 源码继续保留为事件类型来源，其 Apache-2.0 许可、NOTICE 和修改说明位于 `vendor/codex-sdk/`。0.3 不再使用 SDK exec 作为运行入口。

公开仓库不包含完整 Codex Desktop 前端源码。NEXIOM 前端独立实现，参考其侧栏、会话、输入区和工具记录布局；不声称是官方桌面版源码的改名版本。详见 [第三方声明](THIRD_PARTY_NOTICES.md)。

当前仍使用随应用分发的 Codex 开源引擎，不需要安装或登录 Codex 客户端。Claude Code 是可选的后续内核方向，本次没有迁移内核。Thinking Orbs 与 Motion 按 MIT 使用；其余设计网站及科学 Agent 仅作研究，具体来源和取舍见 [网页研究](docs/08-design-agent-research.md)。
